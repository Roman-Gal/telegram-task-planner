# Telegram Task Planner

Україномовний Telegram-бот: один учасник групи створює завдання іншому, а бот нагадує про нього у вказаний час. Окремий проєкт за принципом [telegram-ukrainian-translator](https://github.com/Roman-Gal/telegram-ukrainian-translator): Node.js, Telegram webhook та локальний сервер через ngrok. Код планнера реалізований окремо.

## Можливості

- Меню `/menu` із кнопками «Нове завдання» та «Усі завдання».
- Покрокове створення: виконавець, календар, година/хвилини, опис, пріоритет, нагадування, підтвердження.
- Пріоритети: 🟢 низький, 🟡 середній, 🔴 високий.
- Множинний вибір завчасних нагадувань: за 5, 15, 30 хвилин та 1 годину.
- У строк і потім кожні 15 хвилин — «ПРОТЕРМІНОВАНО» до виконання або скасування, без ліміту кількості повторів.
- Призначення через відповідь на повідомлення, `@username` або `me` для себе.
- Вибір виконавця прямо в групі через `@username`, Telegram-згадку імені або відповідь на повідомлення, без додаткових API-ключів.
- Опис, дата й час; збереження в SQLite після перезапуску.
- Нагадування у групі та додатково в особистому чаті, якщо виконавець натиснув `/start` у боті.
- Кнопки «Виконано», «+15 хв», «Скасувати» та відповідні команди.
- Єдиний список усіх завдань групи зі статусами та сторінками по 10; активні завдання показуються першими.
- Підтримка тем форуму: нагадування повертається в тему створення завдання.
- Змінювати завдання можуть тільки його автор і виконавець.
- Персистентна черга вебхуків, перевірка секрету та захист від дублювання завдань при повторній доставці update.
- Окремі стани доставки для групи й особистого чату, повторні спроби при тимчасових помилках.
- Окремі чернетки для користувачів, груп і тем; збереження кроків у SQLite на 30 хвилин, захист від чужих і застарілих кнопок.

## Потрібно

1. **Node.js 22.22+** (перевірено на 22.22.3). Використовується вбудований `node:sqlite`; Node 22 може показувати попередження про experimental API. Зовнішніх npm-залежностей немає.
2. Токен Telegram-бота від [@BotFather](https://t.me/BotFather). Його можна додати пізніше — без токена доступні всі локальні тести.
3. Встановлений [ngrok](https://ngrok.com/download), обліковий запис і налаштований authtoken.

Планнер призначений для **групи/супергрупи або групи обговорення каналу**. Звичайні дописи каналу й анонімні адміністратори не дають потрібної ідентичності автора, тому не обробляються. Особистий чат підтримує власні завдання та керування своїми груповими завданнями.

## Налаштування Windows

У PowerShell у папці проєкту:

```powershell
npm.cmd ci
Copy-Item .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Вставте у `.env` токен і згенерований секрет:

```dotenv
TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN
WEBHOOK_SECRET=YOUR_GENERATED_RANDOM_SECRET
PUBLIC_BASE_URL=
PORT=8080
HOST=127.0.0.1
TIMEZONE=Europe/Warsaw
DATABASE_PATH=./data/planner.sqlite
ALLOWED_CHAT_IDS=
```

Реальні значення зберігаються тільки в `.env`, який виключений із Git. `WEBHOOK_SECRET` — окремий секрет, не токен бота й не ngrok authtoken.

Один раз налаштуйте ngrok:

```powershell
ngrok config add-authtoken YOUR_NGROK_AUTHTOKEN
```

Якщо ngrok встановлено локально в `.tools/ngrok/ngrok.exe`, скрипт запуску знайде його без додавання до PATH. Для цього варіанта налаштуйте локальний файл конфігурації:

```powershell
.\.tools\ngrok\ngrok.exe config add-authtoken YOUR_NGROK_AUTHTOKEN --config .\.tools\ngrok\ngrok.yml
```

Каталог `.tools/` із програмою та особистою конфігурацією виключений із Git. Якщо локального `ngrok.yml` немає, використовується стандартна конфігурація ngrok.

### Автоматичний тунель і запуск

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-ngrok.ps1
```

Скрипт запускає ngrok приховано, отримує HTTPS-адресу через його локальний API на `127.0.0.1:4040`, передає `PUBLIC_BASE_URL` процесу бота та запускає `npm start`. Значення `PUBLIC_BASE_URL` у `.env` для цього режиму не потрібне. `Ctrl+C` завершує бота й запущений скриптом ngrok. Якщо ngrok уже використовує порт 4040, скористайтеся ручним режимом. Лог ngrok зберігається локально в `data/ngrok.log`.

### Ручний режим, також Linux/macOS

Перша консоль:

```sh
ngrok http 8080
```

Скопіюйте HTTPS origin тунелю в `PUBLIC_BASE_URL` файлу `.env`, наприклад `https://your-domain.ngrok-free.app`. Не додавайте шлях `/telegram/webhook` — бот додає його сам.

Друга консоль:

```sh
npm start
```

При запуску бот перевіряє токен, реєструє меню команд і встановлює вебхук з `secret_token`. Після зміни адреси ngrok оновіть `.env` і перезапустіть бота. Черга Telegram при реєстрації не очищається.

### Перезапуск у Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\restart.ps1
```

Скрипт перевіряє PID, назву процесу та час запуску з `data/runtime.json`, зупиняє тільки це дерево процесів планнера, зберігає резервну копію SQLite разом із WAL, запускає бота й ngrok приховано та перевіряє локальний `/health`. Якщо бот був запущений вручну в консолі, спочатку зупиніть його через `Ctrl+C`. Інші процеси Node.js та ngrok не завершуються.

Після перезапуску дані й чинні чернетки залишаються в SQLite. Щоб почати нове завдання замість старої чернетки, використайте `/menu` → «Нове завдання». Перезапуск не продовжує строк дії простроченої чернетки. Старі кнопки чинної чернетки показують поточний крок без повторного застосування попередньої дії; на текстових кроках є актуальні «Назад» та «Скасувати».

## Налаштування Telegram

1. Додайте бота у групу. Для перевірки актуального учасника через `@username` рекомендовані права адміністратора: Telegram гарантує `getChatMember` для інших користувачів саме ботам-адміністраторам. Призначення відповіддю на повідомлення не потребує такого запиту.
2. Учасники визначаються автоматично з доступних боту повідомлень, відповідей, натискань меню та подій входу/виходу. Окремої реєстрації немає. При відкритті створення завдання бот також оновлює список адміністраторів групи.
3. Для особистих нагадувань кожен виконавець відкриває бота й натискає `/start`. Бот не може сам почати приватну розмову з користувачем.
4. Надсилайте команди боту; у групах з кількома ботами можна використовувати `/task@your_bot_username`. Загальне читання повідомлень і вимкнення Privacy Mode для основного сценарію не потрібні.
5. За бажанням обмежте роботу конкретними групами через `ALLOWED_CHAT_IDS=-1001234567890,-1009876543210`. Особисті чати залишаються доступними для власних завдань і нагадувань.

## Приклад

### Рекомендовано: меню в групі

1. Напишіть `/menu` та закріпіть повідомлення стандартною дією Telegram «Закріпити».
2. Учасники з'являються у списку автоматично. Прізвище, ім'я та username доступні для пошуку; username не обов'язковий. Для людини, яку бот ще не бачив, достатньо написати `/task` відповіддю на її повідомлення — виконавця буде вибрано автоматично.
3. Натисніть «➕ Нове завдання» → **«👤 Вказати через @»**. У відповіді на запит бота введіть `@` та оберіть учасника в підказках самого Telegram. Вибір залишається в групі. Або натисніть ім'я відомого учасника безпосередньо у списку кнопок. Далі виберіть дату, годину та хвилини; для точного часу, наприклад `18:37`, є кнопка текстового вводу.
4. Опишіть завдання **відповіддю на запит бота**. Так само працює пошук і введення точного часу. Telegram відкриває поле відповіді через ForceReply; загальні повідомлення групи не стають описом випадково.
5. Виберіть пріоритет і одну або кілька кнопок нагадувань. Повторне натискання знімає вибір. Типово вибрано 15 хвилин; можна вимкнути всі завчасні нагадування.
6. Перевірте картку та натисніть «✅ Створити». До підтвердження завдання не зберігається як активне й не надсилає нагадувань.

`/task` без аргументів теж запускає цей сценарій. `/cancel` без ID скасовує поточну чернетку. Списки мають кнопки відкриття конкретного завдання та переходу між сторінками.

Нагадування надходять **і в початкову групу/тему, і приватно виконавцю**, якщо він увімкнув приватні повідомлення через `/start`. Завершити чи скасувати завдання можуть автор і виконавець, зокрема з приватної картки.

Telegram-згадка імені без username (`text_mention`) містить ID людини й може вибрати навіть невідомого боту учасника. Звичайний `@username` містить тільки текст: для нього потрібен профіль, уже відомий боту з повідомлення, приватного `/start` чи іншої дії. Бот перевіряє поточне членство через `getChatMember`, зокрема для профілів, відомих лише з приватного чату. Якщо username ще невідомий, нехай людина напише будь-яке повідомлення у групі або надішліть `/task` відповіддю на її повідомлення. Немає окремої реєстрації й не потрібні `api_id`/`api_hash`. Джерела: [MessageEntity](https://core.telegram.org/bots/api#messageentity), [getChatMember](https://core.telegram.org/bots/api#getchatmember).

### Швидкі текстові команди

Старий формат залишається доступним; такі завдання мають середній пріоритет, повідомлення у строк і повтори прострочення, без завчасних нагадувань.

Коротка команда `/task @username` одразу обирає виконавця й відкриває календар; решту полів заповнюють кнопками. Так само працює `/task` із вибраною через Telegram згадкою імені.

```text
/task @buyer | завтра 18:30 | Сходити в Бедронку: масло, хліб, вода
```

Або відповіддю на повідомлення виконавця:

```text
/task завтра 18:30 | Сходити в Бедронку: масло, хліб, вода
```

Для себе:

```text
/task me | завтра 09:00 | Забрати посилку
```

Абсолютна дата: `/task me | 2026-12-01 18:30 | Забрати посилку`. Дата має бути в майбутньому. Також приймаються `сьогодні`, `завтра`, `today`, `tomorrow`; розділювач полів — `|`, тому його не слід використовувати в описі. Опис — до 1200 символів.

Усі введені дати й повідомлення використовують `TIMEZONE` (типово **Europe/Warsaw**), а база зберігає UTC timestamp. Неіснуючий або двозначний час при переході на літній/зимовий час відхиляється з поясненням. Зміна `TIMEZONE` не змінює момент уже запланованих нагадувань.

| Команда | Дія |
| --- | --- |
| `/start` | Довідка; в особистому чаті також увімкнення особистих нагадувань |
| `/help` | Довідка |
| `/menu` | Меню з кнопками та покрокове створення |
| `/id` | Показати власний числовий Telegram user ID |
| `/task ...` | Нове завдання |
| `/tasks`, `/tasks 2` | Усі завдання поточної групи: відкриті, виконані та скасовані, сторінка 1 або 2 |
| `/done 1` | Позначити завдання №1 виконаним |
| `/snooze 1` | Перенести строк виконання на 15 хвилин від поточного моменту |
| `/cancel 1`, `/cancel` | Скасувати завдання №1 або поточну чернетку |
| `/stop` | В особистому чаті вимкнути особисті нагадування |

У групі список містить тільки завдання цієї групи. У приватному чаті `/tasks` показує завдання, де користувач є автором або виконавцем; чужі приватні завдання не показуються. Окремих розділів «Мої» та «Створені мною» немає.

## Надійність і поточні межі

- Bot API не надає повний список звичайних учасників наявної групи. З увімкненим Privacy Mode бот бачить обмежений набір повідомлень; як адміністратор — більше повідомлень і події `chat_member`. Список поповнюється автоматично з отриманих подій, але бот не може відразу показати всіх людей, яких ще не бачив. Призначення відповіддю на повідомлення працює для таких людей без реєстрації.
- Бот і ngrok мають працювати, а комп'ютер — залишатися ввімкненим без сну. Нагадування перевіряються щосекунди, але доставка залежить від Telegram та мережі. Це не сервіс із гарантією доставки в точну секунду.
- У строк виконання надходить перше повідомлення «ПРОТЕРМІНОВАНО», потім — кожні 15 хвилин, поки автор або виконавець не завершить чи не скасує завдання. Пріоритет не змінює цей інтервал.
- Після простою надсилається одне актуальне прострочення; наступне — через 15 хвилин. Немає пачки всіх пропущених повторів. Якщо пропущено кілька завчасних нагадувань, надсилається тільки найсвіжіше; нагадування, час яких минув ще до створення/перенесення завдання, пропускаються.
- Стани доставки зберігаються окремо для кожного моменту та адресата, тому успішне групове повідомлення не повторюється через помилку особистого. Коли настає нове нагадування, застарілі невдалі доставки попереднього не накопичуються.
- При збої точно між прийняттям повідомлення Telegram і записом результату в SQLite повідомлення може повторитися: зовнішній API не підтримує нашу транзакцію. Створення завдання й відкладення захищені від повторного застосування одного update.
- Помилки мережі, `429` і `5xx` повторюються з паузою; враховується `retry_after`. Для нагадувань — максимум 10 спроб, для вхідних update — 8. Постійні `4xx` завершують конкретну доставку. Коди помилок пишуться в консоль без токенів чи текстів повідомлень.
- Після блокування бота особисті нагадування вимикаються; повторний `/start` увімкне їх знову. `/stop` не вимикає групові повідомлення.
- Один процес бота на один токен і файл SQLite. Не запускайте кілька копій, `npm dev` та `npm start` одночасно. Для переходу групи на інший chat ID потрібне окреме перенесення даних.
- Підтримуються одноразові завдання, один виконавець і один часовий пояс. Повторювані самі завдання та редагування вже підтвердженого завдання поки не реалізовані; перед підтвердженням можна повернутися до потрібного кроку.
- Runtime-дані лежать у `data/` і не потрапляють до GitHub. Для резервної копії зупиніть бота й скопіюйте весь каталог `data/`. Не видаляйте його між запусками.
- При першому запуску нової версії SQLite автоматично мігрує схему, зберігаючи наявні завдання, користувачів і результати доставок. Старі завдання отримують середній пріоритет і не мають завчасних нагадувань. Перед оновленням зберігайте резервну копію бази.
- Звук сповіщень вибирає кожен користувач у налаштуваннях Telegram для чату з ботом. Bot API не дозволяє задавати окрему мелодію залежно від пріоритету завдання.

## Додавання бота тільки власником

У `.env` можна задати `OWNER_USER_ID` — числовий Telegram ID власника. Власник отримує свій ID командою `/id` у приватному чаті з ботом. Username не використовується для перевірки власника.

```dotenv
OWNER_USER_ID=YOUR_NUMERIC_TELEGRAM_USER_ID
```

Після перезапуску:

- Нова група автоматично дозволяється, коли Telegram повідомляє, що бота додав цей власник. Користуватися планнером у дозволеній групі можуть усі учасники.
- Якщо інший користувач додає бота, бот виходить через `leaveChat` і не обробляє завдання цієї групи. Подальші звичайні зміни прав бота іншими адміністраторами в уже дозволеній групі не заважають роботі.
- Для групи, де бот уже був до ввімкнення обмеження, власник надсилає `/allow` у цій групі. Це одноразовий дозвіл для групи, не реєстрація учасників. Початково дозволені групи також можна явно вказати в `ALLOWED_CHAT_IDS`.
- Після виходу/видалення бота дозвіл відкликається. Повторне додавання іншою людиною не успадковує старий дозвіл.
- Без `OWNER_USER_ID` перевірка власника не активна: діє попередня політика `ALLOWED_CHAT_IDS` (порожній список дозволяє групи).

Telegram не надає BotFather-налаштування «додавати може тільки конкретний user ID». `/setjoingroups` у BotFather лише глобально дозволяє або забороняє додавання; наш контроль спрацьовує після події додавання. Джерела: [BotFather settings](https://core.telegram.org/bots/features#edit-settings), [ChatMemberUpdated](https://core.telegram.org/bots/api#chatmemberupdated), [leaveChat](https://core.telegram.org/bots/api#leavechat).

## Перевірки

```sh
npm ci --ignore-scripts
npm run check
npm test
```

Тести не потребують токена чи ngrok. Вони перевіряють повний сценарій меню, календар і точний час, кілька нагадувань, пріоритет, паралельні чернетки та чужі кнопки, повторні callback без подвійного створення, перенесення старої бази, розклад прострочення, права доступу, ізоляцію груп, DST, секрет вебхука, персистентність і повторні доставки. HTTP-тести використовують локальний loopback. GitHub Actions запускає перевірки на Windows та Linux.

Автоматичні тести використовують імітацію Telegram. Після налаштування справжнього токена й ngrok перевірте `/menu` та створення завдання у своїй групі.

## Docker для майбутнього хостингу

```sh
docker build -t telegram-task-planner .
docker run --rm --env-file .env -p 127.0.0.1:8080:8080 -v planner-data:/app/data telegram-task-planner
```

Контейнер слухає `0.0.0.0`; у `.env` для Docker задайте `HOST=0.0.0.0` та `DATABASE_PATH=/app/data/planner.sqlite` (значення `.env` перекривають Dockerfile). Тунель або HTTPS reverse proxy все одно потрібен. Не вбудовуйте `.env` у Docker image.

```text
src/index.js          запуск, реєстрація вебхука, фонові процеси

src/planner.js        команди, права, картки завдань, нагадування

```
